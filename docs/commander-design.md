# 指挥模式设计（让大模型自己定打法）

状态：2026-09-25。第一步（简报与请求）和第二步（接入托管，0.7.0）已实现；第三步待实战验证后再做。

## 为什么要改

到 0.6.1 为止，扩展用几千行手写规则先把局面想一遍，每组只挑出 2–6 个「候选动作」，模型只做选择题。实战里反复出现的问题几乎都出在规则这一层：

- 规则漏想的，模型选不到：五角大楼从没进过候选；另一侧的碉堡不在名单里。
- 规则想错的，模型纠正不了：装饰物被当成占领目标；只打飞机的爱国者占满进攻名额；「射程外受击就抵近还击」变成拿步兵冲碉堡。
- 每修一处又冒出新问题，规则越来越多、互相牵制（兵少不进攻 × 步兵上限 → 整局卡死 65 分钟）。

目标：**扩展负责「看清」和「执行」，打法交给模型**。模型看到规则（每种单位能做什么）和态势（现在谁在哪、谁压制谁），自己决定各支部队做什么。

## 三层分工

| 层 | 负责 | 内容 |
| --- | --- | --- |
| 知识与态势 | 扩展（自动生成） | 单位能力卡、当前态势、上一轮计划的结果、可用的合法目标 |
| 指挥 | 模型 | 每支小队的意图、要造什么、工程师做什么，每条附一句理由 |
| 执行与本能 | 扩展（固定规则） | 把意图翻译成游戏命令；保留必须实时的本能：还手 / 撤出射程、基地告急自救、集火 |

两种模式并存，在设置里切换：

- **选择题模式**（现有，默认）：Jev、本地 Laya、以及想保持原样的场合。
- **指挥模式**（新增）：仅「OpenAI 兼容」来源（gpt、DeepSeek 等大模型）。本地 Laya 每组题只能读约 256 token、不会推理，做不了指挥。

## 第一层：知识卡与态势简报

### 单位能力卡（从 `api.rules` 自动生成，只列本局出现过或可以生产的单位）

每种单位一行，字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 代号，如 `E2` |
| `name` | 显示名，如 `Conscript` |
| `kind` | infantry / vehicle / aircraft / ship / building / defense |
| `cost`、`speed` | 价格、速度 |
| `armor` | 护甲类别 |
| `range` | 对地射程、对空射程（没有则为 0） |
| `vs` | 每秒伤害估算，分别对：步兵、装甲、建筑、飞机（用武器伤害 × 护甲倍率 × 射速，已有 `weaponEffectiveness`） |
| `tags` | 能进楼 / 可被驻守 / 工程师 / 采矿 / 可部署 / 只能打飞机 / 修桥小屋 / 装饰物 等 |

建筑额外标：是否防御、是否只对空、是否可驻守（容量）、是否可占领。

### 态势简报（每次决策生成）

| 部分 | 内容 |
| --- | --- |
| 概况 | 游戏时间、资金、电力、近期收入、本局目标及匹配结果 |
| 生产 | 各队列状态；现在能造什么（代号 + 价格） |
| 我方小队 | 按位置和当前任务自动分组、编号稳定：小队号、兵种 × 数量、中心坐标、平均血量、当前意图及执行情况、是否在挨打（被谁打、对方射程是否比我们远） |
| 我方基地 | 建筑清单与位置、是否受攻击、可驻守民房 |
| 敌方 | 看得见的部队按位置聚成群（兵种 × 数量、中心、离哪支小队多远）；看得见和记得住的建筑（编号、名称、坐标、防御射程、是否只对空） |
| 关系 | 哪些敌方防御 / 部队的射程压着我方哪支小队；每座敌方防御附近 8 格内的空民房 |
| 地图 | 受损的桥和对应修桥小屋；可占领的科技建筑；未探索的方向 |
| 上一轮 | 每条意图：是否执行、目标血量变化、我方损失 / 击杀，失败原因 |

篇幅目标：3,000–6,000 token。每个坐标、编号都真实存在，模型下意图只能引用简报里出现的编号。

## 第二层：意图动作表（模型的输出）

模型用函数调用回答，结构：

```json
{
  "squads": [{ "squad": "S1", "action": "attack", "target": 1655, "reason": "…" }],
  "production": [{ "item": "E2", "count": 5, "reason": "…" }],
  "engineers": [{ "action": "repair_bridge", "target": 1607, "reason": "…" }],
  "note": "一句话说明本轮总体打法"
}
```

| 动作 | 参数 | 执行 |
| --- | --- | --- |
| `attack` | 目标编号（敌方单位 / 建筑） | 指定目标攻击 |
| `attack_move` | 坐标 | 边走边打 |
| `move` | 坐标 | 移动，不主动交战 |
| `hold` | 坐标 | 走到后原地防守 |
| `garrison` | 民房编号 | 派小队里的步兵进楼（受容量限制） |
| `defend_base` | 无 | 回防，打基地附近威胁 |
| `retreat` | 无 | 撤回集结点整补 |
| `scout` | 坐标 | 派小队里最快的一个去探路 |
| `train` | 单位代号、数量（≤5） | 进队列生产 |
| `build` | 建筑代号 | 进队列，位置由扩展选 |
| `capture` / `repair_bridge` | 目标编号 | 派空闲工程师 |

没提到的小队保持当前意图。所有编号、代号、坐标都校验：不存在或不合法的那一条丢弃并在下一轮「上一轮结果」里告诉模型原因，其余照常执行。

## 第三层：执行与本能（固定规则，保留、不扩张）

- 意图翻译成现有的命令形式（进攻、驻守、生产、工程任务都复用现有执行代码）。
- 同一意图持续期间：只给新加入或空闲的单位补发命令，不打断正在交火的兵。
- 本能反应（每 150 ms，不问模型）：被射程更远的敌人打时还手或撤出射程；少量步兵不冲碉堡；集火；基地告急且模型本轮未处理时自动回防。
- 生产落位、采矿、修理建筑照旧由扩展处理。

不再保留的：针对具体问题写死的战术判断（候选名单截取、出击门槛、自动兜底等）在指挥模式下不使用。

## 节奏与成本

- 每约 12 秒游戏时间决策一次；以下情况立即决策：基地刚受攻击、某支小队损失过半、意图目标被摧毁、首次看到敌方建筑或本局目标。
- 按一局 20 分钟、每次 3,000–6,000 token 估算，总计几十万 token（0.5.8 那局选择题模式用了 1,400 万）。
- 大模型回答要 3–25 秒；两次决策之间由执行层和本能层维持。

## 记录

每次决策写一条 `command` 日志：简报篇幅、意图、每条的执行结果、模型的总体说明和每条理由。数据面板逐条展示。这样出了问题能分清是模型判断错了，还是简报漏了信息。

## 落地步骤

1. **知识卡 + 态势简报 + 日志**：两种模式下都生成，写进日志；用模拟的真实场景（路两侧碉堡、爱国者、五角大楼、断桥）让 gpt / DeepSeek 读简报下意图，检查判断是否合理。
2. **指挥模式**：设置里可切换；执行、校验、节奏、本能层；数据面板展示。
3. **按实战收规则**：指挥模式验证有效后，再决定哪些选择题模式的补丁可以删除。
