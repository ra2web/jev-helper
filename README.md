# jev-helper · 王二火大 WannaFire

Chrome / Edge Manifest V3 扩展。配置模型密钥（或本地模型地址）、API 地址和游戏页快捷键，即可一键接管正在运行的对局。无需 Node 代理、控制台代码或重新构建游戏。

官网：[《王二火大》](https://wangerhuoda.com/) · [WannaFire official website](https://wannafire.com/)。扩展弹窗底部和使用说明的官网入口随语言切换：中文显示「王二火大」并打开 wangerhuoda.com，英文显示「wannafire」并打开 wannafire.com，均使用新标签页。

当前版本：**0.4.3**。各版本改了什么见 [更新记录](#更新记录)。

## 安装与使用

1. 将发布 ZIP 解压到固定目录（ZIP 可在本仓库 Releases 页下载）。在 Chrome 的 `chrome://extensions`（Edge 为 `edge://extensions`）打开「开发者模式」，点击「加载已解压的扩展程序」，选择含 `manifest.json` 的目录。本地开发可直接选择本项目的 `dist/`。
2. 打开扩展弹窗，进入「设置」，先在顶部选择「模型来源」：
   - **Jev 云端**：填写密钥，也可选择「从本地 .env 配置导入」读取已有的 `JEV_API_KEY`、`JEV_BASE_URL`、`JEV_MODEL`。其他字段不会保存或发送。API 默认 `https://api.typesafe.ai/v1`，也接受完整 `/systemone` 地址；自定义服务必须实现 Jev 的候选 Choice 协议，不是普通 Chat Completions 接口。
   - **本地 Laya**：先按 [本地模型使用说明](docs/local-laya.md) 启动本机服务，再填地址（和局域网令牌）。

   保存时只申请所填 API 域名的访问权限。
3. 点快捷键输入框，按下组合键并保存。默认 `Alt+Shift+J`，作用于游戏页面；浏览器地址栏或聊天输入框中不触发。「测试模型连接」只发送一次无游戏动作的候选选择请求（Jev 云端可能产生少量模型费用），结果直接显示在按钮上；成功后再开局。
4. （可选）打战役关卡时，在「本局目标」里写上任务目标，例如「摧毁地图东北角的五角大楼」，详见 [出击策略与战役目标](#出击策略与战役目标)。
5. 在 `https://ra2web.github.io/` 正常进入对局，点击「开启托管」。再次点击「停止」或按快捷键即可接手。关闭弹窗仍继续运行。已打开的游戏页建议在安装扩展后刷新一次，确保快捷键监听器加载；工具栏按钮可直接注入当前页面。

也预先支持 `wangerhuoda.com`、`www.wangerhuoda.com` 和 `staging.wangerhuoda.com`。localhost / 127.0.0.1 调试页可通过点击扩展注入；首次点击前不注册这些调试页的快捷键。页面必须暴露兼容的 `window.werhd` 玩家 API。

### 密钥、安全与停止规则

密钥保存在本机浏览器扩展存储，不同步、不注入游戏页面、不记录到日志。它不是系统钥匙串加密存储。可在弹窗清除。更换服务域名需重新输入相应密钥。模型请求由扩展后台发出，拒绝重定向，网页不能指定请求 URL 或读取密钥。

HTTP 401/402/403 会显示具体状态并立即停止托管；服务恢复或修改配置后手动开启。每局默认 2000 次请求上限，达到后停止，不等于游戏结算或费用上限。不会自动接管下一场比赛。

## 本地部署 Laya 模型

除了 Jev 云端，扩展还能使用在本机 Apple 芯片上运行的 Laya 决策模型：不需要密钥、不产生费用，可局域网共享，但决策质量明显弱于 Jev，属实验用途。模型来源、服务端启动、扩展里要填的地址与令牌、请求 / 响应格式和常见问题，见 **[本地模型使用说明（docs/local-laya.md）](docs/local-laya.md)**。

## 功能详解

### 出击策略与战役目标

原策略按遭遇战写死：进攻选项只在「至少 8 辆地面作战车辆（有敌机时另加 2 辆机动防空）」时出现，探图只在「从未见过敌方建筑」时提供。战役关卡常常造不出车、只能出步兵或根本不能生产，于是永远卡在集结和生产。现在：

- **出击门槛跟着生产能力走**（`state.forceReadiness`，每次决策都附带原因）：能造车按原规则；造不出车时步兵等一切武装单位一起计数；什么都不能造时有多少打多少；部队长时间（2700 tick）没有增长也直接用现有兵力进攻。造不出防空车时不再因为敌机而死等。
- **探图不再因为见过一栋敌方建筑就停止**：只要还不能进攻，就持续派一个可消耗单位向未探索区域推进；侦察兵的训练也随之继续。
- **本局目标**：设置页新增「本局目标（可选）」，例如「摧毁地图东北角的五角大楼」，下次开启托管起随每次决策发给模型，替换默认的遭遇战目标；留空按遭遇战处理。游戏接口不提供任务文本，需要手动填写。

### 后台标签页不停摆

此前决策和微操只靠页面定时器驱动，Chrome 对后台标签页会把定时器压到每分钟一次，而游戏模拟照常推进，于是切走一会儿就会出现「每分钟只问一次、部队原地不动、钱越攒越多」。现在玩家 API 的 `onTick` 每拍检查一次，定时器迟到就立即补跑，标签页在后台也保持正常节奏；停止托管时注销回调。页面不提供 `onTick` 时退回定时器。

### 舰船自卫

海军单位射程内出现敌人时自动开火，即使正在执行模型下达的打击或侦察命令；不参与陆战任务和工厂通道清理。

### 对局战绩

弹窗新增「战绩」标签。每次托管结束（手动、胜负、对局结束、页面刷新）自动记录一场：时长、游戏内时长、模型来源与模型名、请求 / 回答 / 失败次数、平均响应、受理 / 等待动作数、部队峰值、资金起止与峰值、资金与决策曲线、已受理生产、各决策组等待率、本局目标与结束原因。重复停止不重复记录，只监视不托管不记录。最多保留 30 场，可逐场「导出这场 JSON」或「清空战绩」。

### 决策日志

设置页底部新增「决策日志」：扩展在本机记录每次模型问答（各决策组的说明、候选、选择、置信度、概率）、执行结果（受理 / 等待 / 未执行及原因）、请求失败、托管开始结束和对局结果，附带当时的资金、部队、电力等数字摘要；不记录密钥、会话令牌和原始单位列表。最多约 2000 条或 4 MB，超出时丢弃最旧的。

面板直接显示汇总：决策次数、平均响应、受理 / 等待 / 未执行、已受理的生产、各决策组的等待率与常选项。「导出 JSON」把汇总和全部记录下载为 `jev-log-<时间>.json`，「清空日志」删除本机记录。状态摘要里还带有当时的出击就绪状态与原因。

离线分析：

```sh
node tools/analyze-log.mjs <导出的 json 或 laya --log 文件>
```

打印同样的汇总并列出全部选择等待的比例。本地 Laya 服务加 `--log <文件>` 会把每次请求另存为 JSON Lines（候选、选择、概率、耗时、状态长度），同一脚本也能分析。

### 设置页

- **模型来源开关**：顶部切换 Jev 云端 / 本地 Laya，两套地址、密钥 / 令牌、模型名各自保存。
- **密钥显示与回填**：JEV 密钥、本地访问令牌右侧有小眼睛按钮切换明文 / 密文；打开设置时已保存的密钥直接回填并默认遮住。输入框里是什么就保存什么，清空并保存即清除；更换 Jev 服务地址时必须重新输入密钥。密钥只返回给扩展自己的弹窗，内容脚本、状态接口、悬浮窗都拿不到。
- **行内错误提示**：哪个输入框有问题，就在它下面标红并写明原因（缺密钥、地址非法或非 HTTPS、模型名 / 快捷键非法、上限超范围等），焦点自动落到第一个出错处。地址、密钥、令牌、模型名保存时自动去掉首尾空格。
- **测试按钮带状态**：「测试模型连接」按钮自身显示测试中 / 成功（含来源、耗时、模型名）/ 失败（含原因），修改设置后自动复位。

### 游戏内悬浮状态窗

- 默认允许展示，**仅在托管已开启且展示设置开启时出现**。快捷键、停止按钮、自动结束托管都会同步隐藏；不会在大厅或未托管时出现。
- 半透明窗口显示托管状态、有效模型回答数、资金、响应耗时、游戏 tick、停止快捷键和当前模型来源。拖动标题可移动，也可聚焦标题后用方向键移动；右侧按钮收起 / 展开。在当前页面内保留位置，刷新后重置。
- 在扩展「设置」中关闭「托管时显示悬浮状态窗」即可隐藏，立即保存、下次仍生效，**不影响托管运行**。语言跟随扩展设置。
- 开始 / 停止采用状态通知；可见且正在托管时约每 1.5 秒读取扩展会话及控制器状态，不额外请求模型或提交游戏命令。窗口不接收密钥、会话令牌或原始模型输出。

### 双语观察台

- 顶部「中 / EN」即时切换并保存语言。英文游戏名为 **WannaFire**。界面、提示、快捷键通知与帮助页均提供两种语言；游戏自身的语言不受影响。英文下单位使用稳定的规则代号（例如 `MTNK`），不伪造游戏未提供的英文译名。
- 「战场」：基地威胁、基地火力覆盖之外的攻击者、己方作战单位、视野内敌军、基地附近敌军、矿车、平均血量、防空、电力、生产队列和己方单位清单。位置图仅显示当前可见的最多 24 个单位/方和基地，自动缩放，不是全图雷达。
- 「趋势」：累计有效模型回答折线；现有资金与扣除生产队列剩余投入后的资金估算双线。支持鼠标查看采样点和左右方向键。模型一次回答可能包含多组选择，回答数、等待选择数和已受理动作数分开显示。
- 打开弹窗时每约 1.5 秒按需读取现有玩家 API，未开启托管也能观察；不调用模型、不提交命令。运行托管时关闭弹窗仍由玩家观测事件记录，停止托管且关闭弹窗后不再采样。
- 图表保留最近 300 个点，采样间隔至少 2 秒，横轴为本机时间；实际间隔也取决于游戏速度。超过 10 秒的采样空缺不连接曲线。数据存于本地扩展 session storage，后台休眠不丢失；每次开启托管、切换新局、刷新页面会重新开始，不保留长期战报。结束对局保留最后快照并标记为非实时。
- 态势来自当前玩家视野，威胁判断沿用本地策略的公开规则分析；不读取迷雾中敌军，不保证估算完整。

### 自动探索、海陆协同、战损统计与结果标记

- **自动探索兜底**：视野里没有敌人、也没有已知敌方建筑时，模型连续三次对探图选「等待」，扩展直接派出第一条前沿探索任务（日志中记为 `auto_explore`），任务未完成时部队不再原地空等。
- **海陆协同**：基地受到舰船威胁时，能打到它的己方舰船一并编入「保卫基地」任务；闲置舰船会主动接近 12 格内能打的敌人。
- **桥梁修理**：桥梁修理小屋不再只看基地 40 格以内，行进路线上任何己方单位 25 格内的小屋都会触发「派工程师检修」候选，没有工程师时提示训练一名。
- **双方兵力与战损**：每次观测统计我方单位 / 建筑数、可见敌方单位 / 建筑数，以及累计新建、我方损失、击毁敌方（只算在我方视野内消失的目标，迷雾中的不计）。「趋势」和每场战绩各有「兵力趋势」「战损累计」两张曲线。
- **结果标记**：对局结束时未战败的场次显示「对局结束 · 未战败」，战绩详情可手动标记胜利 / 战败或清除。游戏接口在任务完成后立即离开对局，扩展来不及读到胜负，战役胜利需要手动标记。

## 开发

```sh
git clone https://github.com/ra2web/jev-helper.git
cd jev-helper
npm ci
npm test
npm run package
```

| 命令 | 作用 |
| --- | --- |
| `npm run build` | 构建到 `dist/`，在扩展管理页重新加载并刷新游戏页即可生效 |
| `npm test` | 构建并运行全部测试 |
| `npm run package` | 构建并在 `artifacts/` 生成发布 ZIP |
| `npm run laya` | 启动本地 Laya 决策服务（见 [docs/local-laya.md](docs/local-laya.md)） |
| `node tools/preview.mjs` | 界面预览，打开 `http://127.0.0.1:4318/` |
| `node tools/analyze-log.mjs <文件>` | 离线分析决策日志 |

`dist/` 可直接加载；ZIP 位于 `artifacts/`。唯一构建依赖是 esbuild，无远程代码、无运行时外部依赖。

界面预览使用模拟数据，只需输入任意测试字符串；不会连接模型或游戏，也不会打包进入扩展。

### 发版

推送到 `main`（含合并 PR）时 GitHub Actions 会自动执行 `npm test` 和 `npm run package`，并按 `package.json` 的版本号发布 Release（标签 `v<版本>`，附带 ZIP 和 SHA-256）。同一版本只发布一次，发新版前先同步修改 `package.json` 与 `public/manifest.json` 的版本号（不一致时工作流直接失败）；PR 只做检查不发版。工作流见 `.github/workflows/release.yml`。

### 目录结构

- `src/player/`：后续策略的维护位置。初始策略来自原工程 `docs/examples/jev/` 的 v8.8.15，射程、编队、防守、科技、部署、驻扎、运输、空军、围墙、变卖与桥梁逻辑保持；0.4.2 起出击门槛与探图规则按生产能力调整。原工程示例是历史接入方案，不会在每次构建时复制覆盖这里的策略。
- `src/page.mjs`：通过公开 `window.werhd` 控制当前玩家；决策走消息适配器，没有密钥和 HTTP 代理地址。
- `src/content.mjs` / `src/overlay.mjs`：隔离环境中的消息桥接、快捷键和托管时的悬浮状态窗。不自动开启托管。
- `src/background-core.mjs`：设置、会话、权限、模型来源选择、Jev / 本地协议、决策日志和错误处理。会话计数存于 session storage，后台休眠/唤醒不重置预算；以标签页、文档和会话标识拒绝过期响应。
- `src/observer.mjs` / `src/telemetry.mjs`：只读观测、压缩快照与有界历史采样。
- `src/i18n.mjs` / `src/charts.mjs`：双语文案和本地 SVG 图表，无外部图表依赖。
- `src/popup.mjs` 与 `public/`：弹窗（观察台、战绩、设置）、说明、图标。
- `tools/laya-server.py` / `tools/laya-server.sh`：本地 Laya 决策服务（`npm run laya`），不打入扩展运行包；使用说明见 `docs/local-laya.md`。
- `tools/analyze-log.mjs`：决策日志离线分析。
- `test/`：既有策略回归及扩展消息、权限、停止、会话边界、双模型来源、决策日志、战役出击规则、拍子唤醒、舰船自卫与战绩测试。

游戏引擎和 API 不在本项目中修改。扩展先用公开战况生成候选，模型（Jev 或本地 Laya）选择候选，执行器复查后提交普通玩家命令。接受命令不等于已经产生游戏效果；策略仍属实验性质。
